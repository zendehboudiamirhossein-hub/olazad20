
## v3.9.2 — رفع باگ «آپدیت اجباری به اپ نمی‌رسد / شما بروز هستید»

- **ریشهٔ باگ**: کلاینت `currentVersionCode` را از manifest اندروید می‌فرستد (میراث بیلد تلگرام، ≈۵۴۶۹۹ — بیلد آزادگرام فقط `CLIENT_VERSION` را بازنویسی می‌کند نه versionCode مانیفست)، ولی کدهای نسخه در پنل عددی کوچک‌اند (پیش‌فرض فرم «1»). مقایسهٔ عددیِ `release.versionCode > currentVersionCode` همیشه false می‌شد → `updateAvailable=false` → دکمهٔ «بررسی به‌روزرسانی» همیشه «شما آخرین نسخه را دارید» می‌گفت و فلگ `forceUpdate` هرگز به اپ نمی‌رسید
- **فیکس**: نسخهٔ واقعی کلاینت از هدر `User-Agent: AzadGram/<version>` خوانده و **مقایسهٔ معنایی** انجام می‌شود (1.9.7 > 1.9.6)؛ مقایسهٔ کد فقط fallback برای فراخوان‌های بدون UA است
- **انتخاب رلیز درست**: اندپوینت version دیگر `orderBy versionCode desc` نیست؛ بین همهٔ رلیزهای فعال، بالاترین **شمارهٔ نسخه** سرویس می‌شود (tie-break: کد، سپس تاریخ) — قبلاً رلیز قدیمی با کد بزرگ‌تر می‌توانست جای رلیز جدید را بگیرد
- **مدیریت بهتر رلیزها**: «کد نسخه» در فرم انتشار اختیاری شد و به‌طور خودکار از شمارهٔ نسخه محاسبه می‌شود (1.9.7 → 10907)؛ سوییچ‌های «آپدیت اجباری» و «فعال» روی ردیف‌های جدول زنده و قابل تغییرند (PATCH)؛ ردیف در حال سرویس با نشان مشخص است؛ متن راهنما با رفتار واقعی کلاینت هم‌خوان شد

## v3.9.1 — رفع قطعی سینک مخاطبین (P2028) + آرام‌شدن طوفان لاگ TIMEOUT

- **رفع باگ «مخاطبین به پنل نمی‌آید»**: سینک مخاطبین (`POST /api/client/contacts`) کلِ دسته (تا ۵۰۰۰ آیتم، هر آیتم یک create/update/delete) را داخل **یک** تراکنش interactive اجرا می‌کرد — حالی که تایم‌اوت پیش‌فرض تراکنش‌های Prisma فقط **۵ ثانیه** است. با چندصد مخاطب، تراکنش وسط کار بسته می‌شد، همهٔ عملیات بعدی با `P2028 (Transaction not found)` می‌شکستند و **کل دسته rollback می‌شد** — یعنی هیچ مخاطبی هرگز به پنل نمی‌رسید و retryهای اپ (v1.9.6) مدام به همان دیوار می‌خوردند (طوفان `contacts sync error` در لاگ‌ها). حالا دسته در **تکه‌های ۱۰۰تایی** و هر تکه در تراکنش خودش با تایم‌اوت ۳۰ ثانیه اجرا می‌شود؛ پیشرفتِ تکه‌های قبلی حفظ می‌شود و retry اپ idempotent به نتیجهٔ نهایی می‌رسد
- **رفع باگ latent حذف دوبارهٔ ردیف تکراری**: ردیفی که هم از مسیر `byTg` و هم `byContactId` پیدا می‌شد (نفر ثبت‌شده با آیدی تلگرام) دو بار delete می‌شد → `P2025` → کل سینک abort. حالا کاندیدها با id دی‌دیوپ می‌شوند
- **قطع طوفان `Error: TIMEOUT` خام در لاگ‌ها**: منبع، لاگ داخلی کتابخانه GramJS بود — حلقهٔ retry اتصال MTProtoSender در هر `client.connect()` ناموفق، دقیقاً **۵ بار** (=`connectionRetries`) خطای خام `Error: TIMEOUT` با stack مینیفای‌شده به stdout می‌ریخت؛ اپ کاربر در هر heartbeat برای نشست PENDING ورود-به-اکانت fetch می‌زد و همین الگوی «۵ خطا در هر ۳۰ ثانیه برای ۱۳+ دقیقه» ساخته می‌شد. حالا کلاینت‌های GramJS با `baseLogger` در سطح `none` ساخته می‌شوند (خروجی خام کتابخانه خاموش؛ خطاهای واقعی همچنان با ساختار `[tg-impersonate:stage]` لاگ می‌شوند)
- **Circuit breaker برای fetch ناموفق توکن ورود**: اگر تولید توکن برای یک نشست PENDING در **۵ تلاش پیاپی** شکست بخورد (مثلاً egress تلگرام میزبان قطع است)، نشست `FAILED` می‌شود (با ردیف audit `client.tg_impersonate.circuit_open`) تا heartbeat دیگر آن را اعلام نکند، اپ polling را قطع کند و ادمین خطای واضح ببیند — به‌جای چرخش بی‌پایان تا سقف ۱۵ دقیقهٔ PENDING
- **دیپلوی**: بدون تغییر اسکیما — فقط کد؛ `prisma db push` لازم **نیست**. نیازی به تغییر/آپدیت کلاینت نیست
- تست: ۲۲/۲۲ پاس (سینک ۲۵۰تایی در ۳ تکه، re-sync idempotent، merge کاربر ثبت‌شده، سناریوی حذف دوباره، circuit breaker کامل، DELETE) + اتصال واقعی GramJS به DC تلگرام با logger خاموش تأیید شد

## v3.8.1 — رفع باگ ورود کامل به اکانت‌های دارای تأیید دومرحله‌ای

- **رفع باگ «ورود کامل به اکانت تلگرام» برای اکانت‌های با رمز دومرحله‌ای (2FA)**: قبلاً بعد از تأیید توکن ورود توسط اپ، پنل خطای `SESSION_PASSWORD_NEEDED` تلگرام را مدیریت نمی‌کرد و نشست هرگز فعال نمی‌شد. حالا پنل مرحله‌ی رمز را طبق پروتکل رسمی تلگرام کامل می‌کند (`account.getPassword` → SRP → `auth.checkPassword`) و مهاجرت بین دیتاسنترها (`auth.loginTokenMigrateTo`) را هم پوشش می‌دهد. رمز دومرحله‌ای باید توسط اپ کاربر ارسال شود:

## استقرار روی Railway

```bash
# 1. ریپو را push کنید (یا از GitHub deploy کنید)
railway init
railway add --database        # PostgreSQL
railway variables set \
  JWT_SECRET="$(openssl rand -hex 32)" \
  CLIENT_API_SECRET="$(openssl rand -hex 32)" \
  PANEL_ACCESS_KEY="$(openssl rand -hex 12)" \
  DISABLE_SEED=1 \
  ALLOWED_RELEASE_DOMAINS="github.com,githubusercontent.com,backblaze.com,objects.githubusercontent.com"

railway up
```

پنل روی `https://<project>.up.railway.app` بالا می‌آید. سپس:

```bash
# 2. ادمین بسازید
railway shell
bun run scripts/create-admin.ts <username> '<رمز قوی حداقل ۱۶ کاراکتر>' SUPER_ADMIN
```

آدرس خصوصی پنل:

```
https://<project>.up.railway.app/<PANEL_ACCESS_KEY>
```

⚠️ **این آدرس را فقط برای ادمین‌ها بفرستید.** ریشه دامنه برای بقیه یک صفحه ۴۰۴ معمولی است و دسترسی ۳۰ روز در مرورگر (کوکی HttpOnly) حفظ می‌شود.

## متغیرهای محیطی

| متغیر | الزامی | توضیح |
|---|---|---|
| `DATABASE_URL` | ✅ | Railway خودش می‌سازد |
| `JWT_SECRET` | ✅ | حداقل ۳۲ بایت — `openssl rand -hex 32` |
| `CLIENT_API_SECRET` | ✅ | حداقل ۳۲ بایت — توکن‌های کلاینت با این امضا می‌شوند |
| `PANEL_ACCESS_KEY` | 🔒 توصیه | مسیر مخفی پنل؛ اگر خالی باشد پنل در ریشه نمایان است |
| `TELEGRAM_BOT_TOKEN` | اختیاری | برای ارسال کد تأیید به تلگرام کاربر |
| `BOT_VERIFICATION_ENABLED` | اختیاری | `true`=کد اجباری، `false`=غیرفعال، خالی=فقط وقتی توکن ربات هست |
| `ALLOWED_RELEASE_DOMAINS` | ✅ | دامنه‌های مجاز لینک دانلود APK |
| `DISABLE_SEED` | ✅ | همیشه `1` |

## ساخت ادمین

```bash
bun run scripts/create-admin.ts admin 'Str0ngP@ssword!Min16' SUPER_ADMIN
```

نقش‌ها: `SUPER_ADMIN` (کامل) · `OPERATOR` (کاربر/کانفیگ/ورود به اکانت) · `SUPPORT` (فقط مشاهده + مسدودسازی)

## اتصال اپلیکیشن

کلاینت اندروید (AzadGram) از این اندپوینت‌ها استفاده می‌کند — آدرس پنل داخل `AzadGramBuildConfig.PANEL_URL` کد کلاینت است:

| اندپوینت | کارکرد |
|---|---|
| `POST /api/client/auth` | ورود با `telegramId` + `phoneNumber` → توکن ۳۰ روزه (در صورت فعال بودن OTP، کد با ربات ارسال می‌شود) |
| `GET /api/client/configs` | کانفیگ‌های کاربر + `shareUri` (اگر کانفیگی نداشته باشد، کانفیگ‌های رایگان فعال پیشنهاد می‌شود) |
| `POST /api/client/connect` | شروع اتصال → `logId` |
| `POST /api/client/heartbeat` | آخرین حضور |
| `POST /api/client/traffic` | گزارش ترافیک (dedup با `requestId`) |
| `POST /api/client/disconnect` | پایان اتصال |
| `POST /api/client/contacts` | سینک مخاطبین — `{ source: 'device'|'telegram', contacts: [{ phoneNumber?, telegramId?, username?, firstName?, lastName? }] }` (v3.7: آیتم بدون شماره با telegramId پذیرفته می‌شود) |
| `GET /api/client/traffic` | آمار مصرف کاربر (پلن، مصرف، باقیمانده) |
| `GET /api/client/guest-config` | کانفیگ رایگان قبل از لاگین (بدون auth) |
| `GET /api/client/version` | بررسی آپدیت (`?currentVersionCode=` اختیاری) |

> نکته امنیتی: ترافیک فقط از `/api/client/traffic` شمرده می‌شود؛ `disconnect` دیگر دوبار شمارش نمی‌کند (باگ نسخه ۲).

## API ادمین

همه مسیرهای `/api/admin/*` با JWT (کوکی HttpOnly یا `Authorization: Bearer`) محافظت می‌شوند و بدون کوکی گیت، حتی وجودشان هم ۴۰۴ است:

`login` · `logout` · `me` · `password` · `stats` · `users` (+`/ban` `/plan` `/configs` `/impersonate`) · `configs` · `logs` · `audit-logs` · `releases` · `settings`

## توسعه محلی

```bash
bun install
cp .env.example .env        # مقادیر را پر کنید (برای تست محلی می‌توانید PANEL_ACCESS_KEY را خالی بگذارید)
bunx prisma db push
bun run create-admin -- admin 'Str0ngP@ssword!Min16'
bun run dev                 # http://localhost:3000
```
